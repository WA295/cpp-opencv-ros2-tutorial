## 1. 十个最常用的代码套路

### 套路 1：收集满足条件的东西

**场景：** 从一堆候选中挑出符合要求的（灯条、轮廓、目标）。

```cpp
std::vector<Item> good_items;          // 收集结果

for (const auto& item : all_items) {
    if (满足条件1 && 满足条件2 && 满足条件3) {
        good_items.push_back(item);
    }
}

if (good_items.empty()) return;        // 别忘了判空！
```

**要点：**
- 先 `push_back` 收集，再统一处理。
- **永远假设可能是空的**：`empty()` 检查能避免一堆崩溃。

### 套路 2：找最大 / 最优

**场景：** 多个目标里选最近的、面积最大的、最像的。

```cpp
Item best;
double best_score = -1e9;             // 初始设一个很小的值

for (const auto& item : items) {
    double score = 打分(item);         // 距离越近分越高 / 面积越大分越高等
    if (score > best_score) {
        best_score = score;
        best = item;
    }
}
```

**要点：**
- 初值要么极小（找最大），要么极大（找最小）。
- 复杂的打分 = 把多个条件加权：`score = w1*a + w2*b + ...`。

### 套路 3：两两配对

**场景：** 把左右灯条配成装甲板；把点配成线。

```cpp
for (size_t i = 0; i < items.size(); i++) {
    for (size_t j = i + 1; j < items.size(); j++) {   // j 从 i+1 开始，避免重复
        double d = distance(items[i], items[j]);
        if (d < 阈值 && 其他条件) {
            // 组成一对
        }
    }
}
```

**要点：**
- `j = i + 1` 是"组合"的标准写法（不重复、不和自己比）。
- 数量大时（>几百）两两比较会慢，需要先排序/分桶优化。

### 套路 4：缓存"上一次"的数据（跨回调共享）

**场景：** 两个回调分别收数据，要互相用。

```cpp
class MyNode : public rclcpp::Node {
private:
    // 成员变量：两个回调都能访问
    CameraInfo last_camera_info_;
    bool has_camera_info_ = false;      // 加个标志位更安全

    void callbackA(const MsgA::SharedPtr msg) {
        last_camera_info_ = msg->camera_info;
        has_camera_info_ = true;
    }

    void callbackB(const MsgB::SharedPtr msg) {
        if (!has_camera_info_) return;   // 数据还没来，先跳过
        // 用 last_camera_info_ ...
    }
};
```

**要点：**
- 共享数据用**成员变量**。
- 多一个 `has_xxx_` 标志位，避免"用还没来的数据"。

### 套路 5：限频 / 抽样

**场景：** 处理太慢，想每 N 次才处理一次。

```cpp
void process() {
    static int counter = 0;
    if (++counter % 3 != 0) return;    // 每 3 次处理 1 次
    // ... 处理
}
```

**变体：按时间限频（更精确）**

```cpp
static auto last_time = std::chrono::steady_clock::now();
auto now = std::chrono::steady_clock::now();
if (now - last_time < std::chrono::milliseconds(100)) return;   // 至少间隔 100ms
last_time = now;
```

### 套路 6：状态机（按阶段做事）

**场景：** 程序分几个阶段（等待目标 → 跟踪 → 开火）。

```cpp
enum class State { Idle, Tracking, Firing };
State state = State::Idle;

void update(bool target_found, double error) {
    switch (state) {
        case State::Idle:
            if (target_found) state = State::Tracking;
            break;
        case State::Tracking:
            if (!target_found)      state = State::Idle;
            else if (error < 1.0)   state = State::Firing;
            break;
        case State::Firing:
            if (!target_found)      state = State::Idle;
            break;
    }
}
```

**要点：** 用 `enum class`（带类型，不会和别的常量冲突）表示状态。

### 套路 7：参数可调（运行时改）

```cpp
// 简易版：全局可调变量 + 界面滑条
int thresholdValue = 100;    // 配 cv::createTrackbar / getTrackbarPos

// ROS 2 版：声明参数，可命令行改
this->declare_parameter("threshold", 100);
int t = this->get_parameter("threshold").as_int();
// 运行时改：ros2 param set /节点名 threshold 150
```

### 套路 8：异常/失败保护

```cpp
cv::Mat img = cv::imdecode(msg->data, cv::IMREAD_COLOR);
if (img.empty()) {                     // 失败就退出，别继续
    RCLCPP_WARN(this->get_logger(), "解码失败");
    return;
}

if (idx < 0 || idx >= (int)vec.size()) return;   // 下标先检查
if (ptr == nullptr) return;                      // 指针先检查
```

**心法：每个可能失败的地方都问一句"失败了会怎样"。**

### 套路 9：日志分级

```cpp
RCLCPP_DEBUG(logger, "细节：x=%f", x);     // 调试用，平时不显示
RCLCPP_INFO(logger, "正常信息");           // 常规
RCLCPP_WARN(logger, "警告：%s", reason);   // 可能有问题
RCLCPP_ERROR(logger, "错误：真的坏了");     // 故障
```

**心法：** 别用 `cout` 刷屏；**降频打印**（`if (++n % 100 == 0)`）避免日志拖慢程序。

### 套路 10：拆分大函数

**原则：一个函数只做一件事。**

```cpp
void processFrame(const cv::Mat& frame) {
    auto mask = findBrightRegions(frame);
    auto bars = filterBars(mask);
    auto armors = pairBars(bars);
    publishBest(armors);
}
```

每个小函数单独测试，出问题容易定位。

## 2. 常见运行时错误与解决

### 2.1 Segmentation fault（段错误）

**现象：** 程序突然退出，终端显示 `Segmentation fault (core dumped)`。

**原因（按概率排序）：**

| 原因 | 例子 | 解决 |
| --- | --- | --- |
| 空指针解引用 | `ptr->x` 而 `ptr` 是 `nullptr` | 用前 `if (!ptr) return;` |
| 数组/容器越界 | `v[v.size()]`、`arr[10]` 而长度 10 | 检查下标范围 |
| 用了未初始化的指针 | `int* p; *p = 1;` | 初始化为 `nullptr` |
| 空 Mat 参与运算 | `frame.empty()` 时直接 `frame.at(...)` | 先 `empty()` 检查 |
| 字符串指针问题 | `char* s = "a"; s[0]='b';` | 用 `std::string` |
| 迭代器失效 | 循环里 `push_back` 还在用旧迭代器 | 换写法 |

**排查步骤：**

1. 在可疑位置**打印**（`cout << "到A"`），看挂在哪一步。
2. 二分注释代码，缩小范围。
3. 用 `gdb` 跑一次看堆栈：`g++ -g ...` 然后 `gdb ./程序`，`run` 后看 `bt`。
4. 检查所有 `[]` 访问和 `->` 解引用。

### 2.2 程序卡住 / 不输出

| 原因 | 现象 | 解决 |
| --- | --- | --- |
| 死循环 | CPU 占满、界面不响应 | 检查 `while` 条件里有没有会变的量 |
| 在等消息 | 一直不进入回调 | 检查话题名、`ROS_DOMAIN_ID`、发布方有没有在发 |
| 窗口没刷新 | imshow 后画面不动 | 别忘了 `cv::waitKey(1)` |
| 锁死锁 | 多线程卡住 | 减少锁的范围；别嵌套锁 |
| 打印没刷新 | 看不到日志 | 加 `endl` 或 `fflush(stdout)` |

### 2.3 结果不对（逻辑错误）

**排查方法（按顺序试）：**

1. **打印中间值**：每个关键变量打印一次，看哪一步开始不对。
2. **对照预期**：这一步"应该有 3 个轮廓"，实际几个？不对就查上游。
3. **从后往前推**：从结果反推，看逻辑链在哪断。
4. **画出来看**：图像问题就 `imshow` 中间结果（掩码、二值图），一眼看出问题。
5. **换数据**：用一张"必然正确"的简单数据测试。

### 2.4 内存越用越多（内存泄漏）

| 原因 | 解决 |
| --- | --- |
| `new` 了没 `delete` | 改用智能指针 |
| 容器只加不减 | 定期 `clear()`；限制最大长度 |
| 回调里不断创建大对象 | 复用成员变量 |
| 图像没释放 | 让 `Mat` 按作用域自动释放 |

**工具：** `valgrind ./程序`（慢但对新手很直观）。

### 2.5 浮点数比较陷阱

```cpp
double a = 0.1 + 0.2;      // 实际是 0.30000000000000004
if (a == 0.3) { }          // 可能为假！
if (std::abs(a - 0.3) < 1e-9) { }   // 正确写法：允许误差
```

**心法：浮点数不要用 `==` 比较，用"差的绝对值 < 一个很小的数"。**

## 3. 编译/链接错误详解

### 3.1 找不到头文件

```
fatal error: opencv2/opencv.hpp: No such file or directory
```

**原因与解决：**

| 原因 | 解决 |
| --- | --- |
| 没装库 | `sudo apt install libopencv-dev` |
| 没告诉编译器库在哪 | CMake 里 `find_package(OpenCV REQUIRED)` + `target_include_directories` |
| 手动编译没加 `-I` | `g++ ... -I/usr/include/opencv4` |
| 路径写错 | 检查大小写和目录 |

### 3.2 undefined reference（链接错误）

```
undefined reference to `cv::imread(std::string const&, int)'
```

**意思：** 声明找到了（头文件 OK），但**实现没链接上**。

**解决：**

- CMake：确认 `target_link_libraries(目标 ${OpenCV_LIBS})` 或 `ament_target_dependencies(...)` 里写了。
- 手动编译：加 `-lopencv_core -lopencv_imgproc` 或用 `pkg-config`。
- 自己写的函数：检查 `.cpp` 文件有没有加入编译（`add_executable` 里有没有它）。

### 3.3 重复定义

```
multiple definition of `thresholdValue'
```

**原因：** 在头文件里**定义**了变量，被多个 .cpp 包含。

**解决：**

- 头文件里用 `extern` 声明，在一个 .cpp 里定义。
- 或把常量写成 `constexpr` / `inline`（C++17）。
- 或放进类里当成员。

### 3.4 模板/类型相关（读不懂就先看"候选函数"那段）

```
no matching function for call to 'foo(int)'
```

**解决：** 对照报错里列出的候选签名，看参数类型/个数差在哪（int vs double、漏了参数、const 问题）。

### 3.5 警告不要完全无视

`-Wall -Wextra` 给出的警告（未使用变量、类型截断、未初始化）**经常就是 bug 的信号**。

## 4. 性能常识

### 4.1 先测量，再优化

```cpp
auto t1 = std::chrono::steady_clock::now();
slow_function();
auto ms = std::chrono::duration_cast<std::chrono::milliseconds>(
              std::chrono::steady_clock::now() - t1).count();
std::cout << "slow_function 用了 " << ms << " ms\n";
```

**别猜哪慢，测出来才算数。**

### 4.2 常见加速手段（从简单到复杂）

| 手段 | 做法 | 效果 |
| --- | --- | --- |
| 降频/抽样 | 每 N 帧处理一次 | 巨大 |
| 减小处理区域 | 只处理 ROI，不处理整图 | 大 |
| 避免无谓拷贝 | 用 `const&` 传参；`Mat` 是引用计数，浅拷贝就够 | 中 |
| 提前退出 | 不满足条件立刻 `return` | 中 |
| 用更简单的算法 | 先阈值再轮廓，别一上来就深度学习 | 大 |
| 并行 | 多线程 / OpenCL / GPU | 大但复杂 |
| 编译优化 | `-O2`、`release` 构建 | 中 |

### 4.3 图像程序的性能心法

- **分辨率是最大的性能杠杆**：960×720 减半到 480×360，耗时约变 1/4。
- **每帧别做重复的事**：能提前算好的（相机内参、模板）就存起来。
- **打印也会拖慢**：日志要降频。

## 5. 写代码的好习惯

1. **小步测试**：写 20 行就跑一次。别攒 500 行。
2. **先跑通再优化**：能出结果 > 好看。
3. **每个函数只做一件事**，超过 100 行就考虑拆。
4. **变量名说人话**：`left_bar_center` 比 `a1` 强一百倍。
5. **边界检查**：空、越界、失败，永远先检查。
6. **打印带编号**：`"到A"、"到B"`，方便定位卡在哪。
7. **改完立刻编译运行**：不要攒一堆改动。
8. **用 git**：每完成一小步就 commit。
9. **注释写"为什么"**，不写"是什么"。
10. **看不懂的代码不要抄**：抄了也要逐行搞懂（或打印验证）。

## 6. 综合排错案例

### 案例 1：程序一收图就崩

**现象：** 编译通过，运行后一收到图就 `Segmentation fault`。

**排查：**

1. 在回调第一行打印 `"进入回调"` —— 确认是回调里崩的。
2. 在 `imdecode` 后打印 `img.empty()` —— 如果图片本身没问题，继续。
3. 在取通道处打印 `channels.size()` —— 发现是 0 或 3？
4. 发现 `msg->data` 是空的，`imdecode` 返回空 Mat，后面 `channels[2]` 越界 → 崩。

**结论：** 对 `imdecode` 结果加 `if (img.empty()) return;`。

**通用教训：** 任何"外部输入"（消息、文件、网络）都要先验证。

### 案例 2：改代码不生效

**现象：** 明明改了参数，运行结果还是老的。

**原因排查：**

1. 忘了重新编译 → `colcon build --packages-select 包名`。
2. 编译了但没 `source install/setup.bash`。
3. 有多个工作空间/多个可执行文件，运行的是旧的（`which 程序` 或用绝对路径确认）。
4. 改的是另一个文件（`grep` 一下确认）。

### 案例 3：收不到 ROS 2 消息

**排查清单：**

```bash
ros2 topic list                  # 话题存在吗
ros2 topic echo /话题名          # 有数据吗
ros2 topic info /话题名 -v       # 发布者/订阅者数量对吗
echo $ROS_DOMAIN_ID              # 两边一样吗
```

常见原因：话题名拼错、`ROS_DOMAIN_ID` 不一致、发布方根本没启动、"还没进入对局所以没数据"。

### 案例 4：识别结果时好时坏

**原因可能是：**

- 环境光变化 → 阈值需要自适应（用 Otsu 或动态调整）。
- 参数只对部分距离有效 → 用可调滑条现场调。
- 图像噪点 → 先模糊。
- 固有算法限制 → 记录失败样本，针对性改进。

**方法：** 打印一组"好"和"坏"的参数值对比，找规律。

### 案例 5：程序越跑越慢

**排查：**

1. 看是不是容器一直在变大（打印 `size()`）。
2. 看是不是每帧都在 `new`/创建大对象。
3. 看日志是不是刷太多。
4. 用计时打印找出慢的那一步。
