## 1. 项目背景与目标

### 1.1 背景

T-DT 校园赛 2027 是一个机器人射击模拟器（Unity 游戏）。它提供：

- **图像**：机器人"眼睛"看到的画面（960×720 JPEG）。
- **状态**：自身血量、朝向、弹药、敌人血量等。
- **相机参数**：内参、畸变。
- **控制接口**：接收你算出的云台角度和"开火许可"。

你的任务：**写一个程序，从画面里找到敌方装甲板，算出该往哪打，并把指令发回游戏。**

### 1.2 目标（一句话）

> 订阅图像 → 识别装甲板 → 解算角度 → 发布控制指令。

## 2. 需求分析：输入输出是什么

**这一步项目开始前必须做，别急着写代码。**

| 项目 | 内容 | 来源 |
| --- | --- | --- |
| 输入 1 | 压缩图像（JPEG） | `/camera/image_raw/compressed` |
| 输入 2 | 自身状态 + 相机内参 | `/autoaim/frame` |
| 输出 | yaw / pitch / 是否开火 | `/target_angles_player_1` |

**明确几件事：**

- **阵营**：当前发的是 `_1`（蓝方）。换红方要改成 `_2`。
- **单位**：角度用度（°），距离用米（m）。
- **坐标系**：yaw 以 Unity +Z 为 0、顺时针为正；pitch 向下为正。
- **周期**：图像约 60~120Hz，不可能也不用每帧都处理。

**输出成代码就是这份"合同"：**

```cpp
// 订阅
"/camera/image_raw/compressed"  -> sensor_msgs::msg::CompressedImage
"/autoaim/frame"                -> tdt_interface::msg::AutoAimFrame
// 发布
"/target_angles_player_1"       -> tdt_interface::msg::SendData
```

## 3. 总体设计：数据流和模块

### 3.1 数据流

```
游戏 ──图像──► /camera/image_raw/compressed ──┐
                                              ▼
                                        imageCallback
                                              │ 解码
                                              ▼
                                        processFrame
   ①降频 ②取通道 ③去噪 ④二值化 ⑤找轮廓
   ⑥筛灯条 ⑦配对成装甲板 ⑧认数字 ⑨PnP 算角度
                                              │
                                              ▼
游戏 ◄──指令── /target_angles_player_1 ◄── SendData

游戏 ──状态──► /autoaim/frame ──► frameCallback
                                     │ 缓存内参/姿态
                                     ▼
                              cameraMatrix_ / last_state_
                              （供 processFrame 用）
```

### 3.2 模块划分

| 模块 | 代码位置 | 职责 |
| --- | --- | --- |
| 节点框架 | `class CampusNode` | 订阅、发布、参数 |
| 图像接收 | `imageCallback` | 解码、转交 |
| 状态缓存 | `frameCallback` | 存内参、畸变、姿态 |
| 核心算法 | `processFrame` | 灯条→装甲板→数字→角度 |
| 数据结构 | `struct lightbar` / `struct Armor` | 装中间结果 |
| 工具函数 | `pointdistance` | 两点距离 |

**设计原则：每个模块只做一件事。** 这样每部分能单独调试。

## 5. 分步实现（每一步都可单独测试）

> **核心方法：小步快跑，每步都能单独跑起来。**
> 下面每一步都给出"要做什么、关键代码、怎么验证"。

### 第 1 步：能把图收下来并显示

```cpp
void imageCallback(const sensor_msgs::msg::CompressedImage::SharedPtr msg)
{
    cv::Mat img = cv::imdecode(msg->data, cv::IMREAD_COLOR);
    if (img.empty()) return;
    cv::imshow("test", img);
    cv::waitKey(1);
}
```

**验证：** 运行节点，游戏进对局，能看到画面在动。
**如果不行：** 先别往下走！去查话题、domain、QoS（见 ROS 2 篇排查）。

### 第 2 步：颜色分离 —— 让灯条"亮"起来

```cpp
std::vector<cv::Mat> channels;
cv::split(img, channels);
cv::Mat red_diff;
cv::subtract(channels[2], channels[0], red_diff);   // 红 − 蓝
cv::imshow("red_diff", red_diff);
```

**验证：** 灯条区域应该明显发亮。
**如果不亮：** 确认队服/灯条颜色；蓝方可能是蓝灯条（要学会举一反三）。

### 第 3 步：二值化 + 找轮廓

```cpp
cv::Mat blurred, binary;
cv::GaussianBlur(red_diff, blurred, cv::Size(9, 9), 0);
cv::threshold(blurred, binary, thresholdValue, 255, cv::THRESH_BINARY);

std::vector<std::vector<cv::Point>> contours;
cv::findContours(binary, contours, cv::RETR_EXTERNAL, cv::CHAIN_APPROX_SIMPLE);

cv::Mat show = img.clone();
cv::drawContours(show, contours, -1, cv::Scalar(0, 255, 0), 2);
cv::imshow("contours", show);
```

**验证：** 灯条应该被绿色轮廓圈出来。

### 第 4 步：筛灯条

```cpp
for (const auto& c : contours) {
    double area = cv::contourArea(c);
    if (area < minAreaValue || area > maxAreaValue) continue;   // 面积

    cv::RotatedRect rect = cv::minAreaRect(c);
    float w = rect.size.width, h = rect.size.height;
    if (w > h) std::swap(w, h);                                  // 归一
    if (h / w < 1.5) continue;                                   // 细长
    if (std::abs(rect.angle) > maxAngleValue) continue;          // 接近竖直

    // 存进 lightbars
}
```

**验证：** 画出来的应该是"灯条"而不是别的杂物。
**参数调不对？** 上滑条！`createTrackbar` + `getTrackbarPos`（见 OpenCV 篇）。

### 第 5 步：配对成装甲板

```cpp
for (size_t i = 0; i < lightbars.size(); i++) {
    for (size_t j = i + 1; j < lightbars.size(); j++) {
        double d = cv::norm(lightbars[i].center - lightbars[j].center);
        // 距离比例合适、高度接近、角度接近、中心连线角度小
        if (d / 平均高度 > 1.5 && d / 平均高度 < 4.0 &&
            高度差 < 平均高度 * 0.5 &&
            角度差 < 15) {
            // 组成一个 Armor
        }
    }
}
```

**验证：** 屏幕上应该出现"完整的装甲板框"。

### 第 6 步：认数字（SVM）

```cpp
// 抠出装甲板区域
cv::Rect r = cv::boundingRect(armor.corners);
r &= cv::Rect(0, 0, frame.cols, frame.rows);     // 防越界
cv::Mat roi = frame(r);
if (roi.empty()) continue;

// 特征提取（和训练时一致！）
cv::Mat gray, feature;
cv::cvtColor(roi, gray, cv::COLOR_BGR2GRAY);
cv::resize(gray, gray, cv::Size(20, 28));
gray.convertTo(feature, CV_32F, 1.0 / 255.0);
feature = feature.reshape(1, 1);

// 预测
armor.number = static_cast<int>(svm_->predict(feature));
```

**验证：** 屏幕上数字应该和实际一致。
**识别不准：** 先把 ROI 和 resize 后的小图显示出来对比。

### 第 7 步：PnP 算角度

```cpp
if (!cameraMatrix_.empty() && !distCoeffs_.empty()) {
    std::vector<cv::Point3f> objectPoints = {
        {-W/2, -H/2, 0}, {W/2, -H/2, 0}, {W/2, H/2, 0}, {-W/2, H/2, 0}
    };
    cv::Mat rvec, tvec;
    bool ok = cv::solvePnP(objectPoints, armor.pnpCorners,
                           cameraMatrix_, distCoeffs_,
                           rvec, tvec, false, cv::SOLVEPNP_IPPE);
    if (ok) {
        double yaw_deg   = std::atan2(tvec.at<double>(0), tvec.at<double>(2)) * 180 / CV_PI;
        double pitch_deg = std::atan2(tvec.at<double>(1), tvec.at<double>(2)) * 180 / CV_PI;
        // ...
    }
}
```

**验证：** 打印 `tvec`，距离合理（不是负数、不是天文数字）；
用 `projectPoints` 把模型投影回画面，框应该和目标重合。

### 第 8 步：发布指令

```cpp
tdt_interface::msg::SendData msg;
msg.yaw = static_cast<float>(world_yaw);
msg.pitch = static_cast<float>(pitch_deg);
msg.if_shoot = true;
send_pub_->publish(msg);
```

**验证：**

```bash
ros2 topic echo /target_angles_player_1 --once
ros2 topic hz /target_angles_player_1
```

游戏里云台应该会跟着动。

### 第 9 步：降频与收尾

- 每 3 帧处理 1 帧（`frameCount % 3`）。
- 日志降频（`% 100`）。
- 参数上滑条。
- 画结果、显示。

## 7. 调试实录：常见问题怎么解决

### 案例 A：收不到图像

**现象：** 节点起来了，但 `imageCallback` 不打印。

**排查过程：**

```bash
ros2 topic list -t | grep camera        # 话题在
ros2 topic hz /camera/image_raw/compressed   # 有频率吗 → 有
ros2 topic info /camera/image_raw/compressed -v  # 订阅数对吗
echo $ROS_DOMAIN_ID                     # 两边一致
```

**最后发现：** QoS 不匹配（发布方 BEST_EFFORT，订阅方 RELIABLE）。
**解决：** 订阅时用 `rclcpp::SensorDataQoS()`。

### 案例 B：程序一跑就崩

**现象：** `Segmentation fault`。

**排查：**

1. 在回调第一行打印 —— 确认崩在回调里。
2. `imdecode` 后打印 `img.empty()` —— 发现是空图。
3. **原因：** 收到一条很小的"心跳"消息，`msg->data` 不含有效 JPEG。
4. **解决：** `if (img.empty()) return;`

### 案例 C：灯条时有时无

**排查：**

1. 把 `red_diff`、`binary` 显示出来 → 发现阈值固定，光照一变就不行。
2. **尝试 1：** 加滑条手动调 → 能调好但换场景就废。
3. **尝试 2：** 用 `THRESH_OTSU` 自动阈值 → 稳多了。
4. **尝试 3：** 加面积/角度约束 → 误检少了。

**结论：** 识别问题要"**看中间结果 + 逐步加约束**"，不要瞎调参数。

### 案例 D：能识别，但瞄准偏

**排查：**

1. `rxvt_plot` 看 yaw 的曲线 —— 发现和实际偏 180°。
2. **原因：** `world_yaw = last_state_.yaw_degrees + yaw_deg` 里，
   `yaw_degrees` 的零位和 `SendData.yaw` 要求的不一致。
3. **解决：** 查接口文档（README）、实测验证符号，加/减 π。

**教训：坐标系约定错了，程序完全正常但结果全反 —— 这类问题要靠文档 + 实测。**

### 案例 E：程序越跑越卡

**排查：**

1. `top` 看 CPU —— 发现自己的节点占满一个核。
2. 用计时打印发现 `processFrame` 里某步很慢。
3. **原因：** 对全图做 `at<Vec3b>` 逐像素遍历。
4. **解决：** 换成 OpenCV 的向量化函数（`split`/`subtract`）。

## 8. 优化方向

按"性价比"排序：

| 优化 | 做法 | 收益 |
| --- | --- | --- |
| 降频 | 每 N 帧处理 1 帧 | 巨大 |
| 缩小处理区域 | 只在画面中央 ROI 找灯条 | 大 |
| 同帧处理 | 直接订阅 `/autoaim/frame`，用里面的图/内参/状态 | 中（更准） |
| 参数自适应 | OTSU、动态阈值 | 中（更稳） |
| 加滤波 | 对 yaw/pitch 做滑动平均 | 中（不抖） |
| 开火策略 | 角度误差 < 阈值才 `if_shoot=true` | 中（更准） |
| 编译优化 | `-O2` / Release 构建 | 小~中 |
| 多线程 | 识别和通信分开线程 | 复杂，慎用 |

**一句忠告：先让它准，再让它快，最后才让它优雅。**

## 9. 可以复用到别的项目的经验

### 9.1 项目启动清单

```
□ 明确输入输出（话题、类型、方向）
□ 准备接口包（复制、编译、ros2 interface show 验证）
□ 建包、配 CMakeLists/package.xml
□ 第 1 步永远先"收数据 + 显示"，确认链路通
□ 之后每个功能一小步，做完就测
```

### 9.2 调试清单

```
□ 收不到数据 → topic list / info / hz / domain / QoS
□ 崩 → 打印定位 + 判空 + 边界检查
□ 结果不对 → 显示中间结果，逐步缩小范围
□ 慢 → 计时打印，先降频再优化
□ 找不到头文件/链接错误 → CMake 配置
```

### 9.3 三个"永远"

1. **永远先验证输入**：外部来的数据（消息/文件）先判空、判范围。
2. **永远小步测试**：改一点跑一次。
3. **永远做可视化**：能画出来的就别只看数字。
