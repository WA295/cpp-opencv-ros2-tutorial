## 1. 终端（命令行）基础

### 1.1 为什么用终端

图形界面点鼠标虽然直观，但：

- 编译、运行、调试命令必须敲；
- 远程服务器没有图形界面；
- ROS 2 的所有工具都是命令行。

所以终端是必修课，但常用命令就那一二十个。

### 1.2 导航与查看

| 命令 | 全称/含义 | 例子 |
| --- | --- | --- |
| `pwd` | print working directory，显示当前目录 | `pwd` |
| `ls` | list，列出目录内容 | `ls -la`（含隐藏文件、详细信息） |
| `cd 目录` | change directory，进入目录 | `cd ~/campus_ws` |
| `cd ..` | 回上一级 | `cd ..` |
| `cd ~` | 回家目录 | `cd ~` |
| `tree` | 用树状图看目录 | `tree -L 2`（只看 2 层） |
| `cat 文件` | 显示整个文件 | `cat package.xml` |
| `less 文件` | 分页查看（`q` 退出，`/关键词` 搜索） | `less big.log` |
| `head -n 20 文件` | 看前 20 行 | `head -n 20 main.cpp` |
| `tail -n 20 文件` | 看后 20 行；`tail -f` 实时滚动 | `tail -f ~/.local/state/.../unity.log` |

**路径小知识：**

- `/` 开头是绝对路径：`/home/robot/campus_ws`
- `~` 代表你的家目录：`~` = `/home/robot`
- `.` 表示当前目录，`..` 表示上一级
- 路径里有空格要加引号：`cd "my folder"`
- 按 `Tab` 键可以自动补全路径/命令（极好用！）

### 1.3 文件操作

| 命令 | 作用 | 例子 |
| --- | --- | --- |
| `mkdir 目录` | 建目录（`-p` 可一次建多层） | `mkdir -p a/b/c` |
| `cp 源 目标` | 复制（`-r` 复制目录） | `cp -r src backup/` |
| `mv 源 目标` | 移动 / 改名 | `mv old.cpp new.cpp` |
| `rm 文件` | 删除（`-r` 删目录，**不可恢复**） | `rm -rf build/` |
| `touch 文件` | 建空文件 / 更新时间 | `touch test.cpp` |
| `ln -s 目标 链接名` | 建软链接（快捷方式） | `ln -s /opt/ros/jazzy/setup.bash ros.sh` |

> ⚠️ `rm -rf` 很危险，敲之前**再看一遍路径**。永远不要敲 `rm -rf /` 或 `rm -rf ~`。

### 1.4 搜索

| 命令 | 作用 | 例子 |
| --- | --- | --- |
| `grep 关键词 文件` | 在文件里搜文字 | `grep -n "yaw" main.cpp`（`-n` 显示行号） |
| `grep -r 关键词 目录` | 递归搜索目录 | `grep -rn "create_subscription" src/` |
| `grep -i` | 忽略大小写 | `grep -i "error" log.txt` |
| `find 目录 -name "*.cpp"` | 按名字找文件 | `find . -name "*.hpp"` |
| `which 命令` | 命令装在哪 | `which python3` |
| `ps aux \| grep 程序` | 看进程在不在 | `ps aux \| grep campus_node` |
| `kill PID` | 结束进程 | `kill 12345`（`-9` 强杀） |

### 1.5 权限与安装

| 命令 | 作用 |
| --- | --- |
| `chmod +x 文件` | 给文件加"可执行"权限（脚本常用） |
| `sudo 命令` | 以管理员权限执行（安装软件等） |
| `apt install 包名` | 装软件（Ubuntu/Debian） |
| `apt remove 包名` | 卸载 |
| `apt list --installed \| grep opencv` | 看装了哪些相关包 |

### 1.6 环境变量

环境变量是"整个系统都能读到的设置"。常见操作：

```bash
echo $HOME                 # 查看某个环境变量的值
export ROS_DOMAIN_ID=7     # 设置/修改（只在当前终端有效）
env                        # 列出所有环境变量
```

**重要：`source` 命令**

```bash
source /opt/ros/jazzy/setup.bash
```

`source` 的意思是"在当前终端里执行这个脚本"，它主要用来**设置环境变量**
（比如把 ROS 2 的可执行文件路径加到 `PATH` 里）。

> 所以每开一个新终端，都要重新 `source` 一次 ROS 和你自己的工作空间。
> 想省事可以写进 `~/.bashrc`（每次开终端自动执行）。

## 2. 编译一个 C++ 程序

### 2.1 最简命令

```bash
g++ main.cpp -o main      # 把 main.cpp 编译成可执行文件 main
./main                    # 运行
```

### 2.2 常用参数（记住这几个就够）

| 参数 | 作用 | 什么时候加 |
| --- | --- | --- |
| `-o 名字` | 指定输出的可执行文件名 | 总是要 |
| `-std=c++17` | 使用 C++17 标准 | 用到新语法时 |
| `-Wall -Wextra` | 打开更多警告（帮你发现隐患） | 建议总是加 |
| `-g` | 生成调试信息 | 要断点调试时 |
| `-O2` | 优化（跑得更快） | 最终版本 |
| `-I 目录` | 额外头文件搜索目录（大写 i） | 用第三方库时 |
| `-L 目录` | 额外库搜索目录 | 用第三方库时 |
| `-l 库名` | 链接某个库（小写 L） | 用第三方库时 |
| `-pthread` | 启用线程库 | 用多线程时 |

例子（用 OpenCV）：

```bash
g++ main.cpp -o main -std=c++17 -Wall \
    $(pkg-config --cflags --libs opencv4)
```

> `pkg-config` 是一个"帮你查库的编译参数"的工具。`--cflags` 给编译参数，`--libs` 给链接参数。

### 2.3 编译到底做了什么（理解这个就不怕报错）

```
main.cpp
  │ ① 预处理：展开 #include、处理 #define        → .i 文件
  │ ② 编译：把 C++ 变成汇编                      → .s 文件
  │ ③ 汇编：把汇编变成机器码（目标文件）          → .o 文件
  │ ④ 链接：把多个 .o 和库拼成可执行文件          → 可执行文件
```

对应到报错：

- **① 阶段错误**：找不到头文件（`fatal error: xxx.h: No such file or directory`）
- **② 阶段错误**：语法错、类型错（`error: ...`）
- **④ 阶段错误**：链接错（`undefined reference to ...`，说明"函数声明有、实现没找到"）

### 2.4 多文件编译

```bash
# 方法一：一次编译所有源文件
g++ main.cpp tool.cpp -o app

# 方法二：分别编译再链接（大项目常用）
g++ -c main.cpp -o main.o      # -c 表示只编译、不链接
g++ -c tool.cpp -o tool.o
g++ main.o tool.o -o app
```

> 项目一大，手敲 `g++` 就不现实了，这时用 **CMake**（下一节）。

## 3. CMake：项目怎么组织编译

### 3.1 为什么需要 CMake

一个 ROS 2 项目可能依赖十几个库、几十个源文件，还要支持不同平台。
CMake 让你**写一份描述文件（CMakeLists.txt）**，然后用一条命令完成所有编译。

### 3.2 最小 CMake 例子（普通 C++ 项目）

```cmake
cmake_minimum_required(VERSION 3.16)   # 要求的最低 CMake 版本
project(my_app)                        # 项目名

set(CMAKE_CXX_STANDARD 17)             # 用 C++17

add_executable(my_app main.cpp tool.cpp)   # 生成可执行文件 my_app

target_link_libraries(my_app pthread)      # 链接线程库
```

编译：

```bash
mkdir build && cd build      # 建一个 build 目录（保持源码干净）
cmake ..                     # 生成 Makefile
make -j4                     # 编译（-j4 表示 4 个任务并行，更快）
./my_app                     # 运行
```

### 3.3 用 OpenCV 的 CMake 写法

```cmake
cmake_minimum_required(VERSION 3.16)
project(opencv_demo)

set(CMAKE_CXX_STANDARD 17)

find_package(OpenCV REQUIRED)          # 找到 OpenCV，并定义 ${OpenCV_LIBS}
find_package(OpenCV REQUIRED COMPONENTS core imgproc highgui)   # 只要部分模块也行

add_executable(demo main.cpp)

target_include_directories(demo PRIVATE ${OpenCV_INCLUDE_DIRS})  # 头文件目录
target_link_libraries(demo ${OpenCV_LIBS})                        # 链接库
```

> `find_package(XXX REQUIRED)` 会在系统里找 XXX 的配置；找到后一般会给你
> `XXX_INCLUDE_DIRS`（头文件目录）和 `XXX_LIBS`（库列表）这两个变量。

### 3.4 ROS 2 包的 CMakeLists 逐行解释

以校园赛项目的 `campus_vision` 为例：

```cmake
cmake_minimum_required(VERSION 3.8)
project(campus_vision)

# 打开编译器警告
if(CMAKE_COMPILER_IS_GNUCXX OR CMAKE_CXX_COMPILER_ID MATCHES "Clang")
  add_compile_options(-Wall -Wextra -Wpedantic)
endif()

# ===== 1. 找依赖 =====
find_package(ament_cmake REQUIRED)     # ROS 2 的构建系统，必须有
find_package(rclcpp REQUIRED)          # ROS 2 C++ 客户端库
find_package(sensor_msgs REQUIRED)     # 传感器消息（图像等）
find_package(OpenCV REQUIRED)          # OpenCV
find_package(tdt_interface REQUIRED)   # 自定义消息包

# ===== 2. 生成可执行文件 =====
add_executable(campus_node src/main.cpp)

# ===== 3. 声明依赖（让 ROS 2 自动加上头文件路径和库）=====
ament_target_dependencies(
  campus_node
  rclcpp
  sensor_msgs
  tdt_interface
)

# ===== 4. 单独链接 OpenCV =====
target_link_libraries(campus_node ${OpenCV_LIBS})

# ===== 5. 安装（ROS 2 要求把可执行文件装到 lib/包名 下）=====
install(TARGETS
  campus_node
  DESTINATION lib/${PROJECT_NAME}
)

# ===== 6. 测试（可以先不管）=====
if(BUILD_TESTING)
  find_package(ament_lint_auto REQUIRED)
  set(ament_cmake_copyright_FOUND TRUE)
  set(ament_cmake_cpplint_FOUND TRUE)
  ament_lint_auto_find_test_dependencies()
endif()

ament_package()    # 必须是最后一句
```

**记忆要点：**

- ROS 2 包 = `find_package` → `add_executable` → `ament_target_dependencies` → `install` → `ament_package()`。
- `ament_target_dependencies` 会自动帮你处理头文件和链接，**比手写 `target_link_libraries` 方便**。
- 用普通第三方库（如 OpenCV）用 `target_link_libraries`。

### 3.5 package.xml：这个包"简历"

`package.xml` 告诉构建系统：这个包叫什么、依赖谁、用什么构建方式。

```xml
<?xml version="1.0"?>
<package format="3">
  <name>campus_vision</name>          <!-- 包名 -->
  <version>0.0.0</version>
  <description>视觉识别节点</description>
  <maintainer email="you@example.com">you</maintainer>
  <license>Apache-2.0</license>

  <buildtool_depend>ament_cmake</buildtool_depend>  <!-- 构建工具 -->

  <depend>rclcpp</depend>            <!-- 依赖（编译+运行都要） -->
  <depend>sensor_msgs</depend>
  <depend>tdt_interface</depend>

  <test_depend>ament_lint_auto</test_depend>

  <export>
    <build_type>ament_cmake</build_type>   <!-- 这是 CMake 类型包 -->
  </export>
</package>
```

**依赖标签的区别：**

| 标签 | 含义 |
| --- | --- |
| `<depend>` | 编译和运行都需要 |
| `<build_depend>` | 只在编译时需要 |
| `<exec_depend>` | 只在运行时需要 |
| `<test_depend>` | 只在测试时需要 |

> 改完 `package.xml` 里加了新依赖，记得在 CMakeLists 里也 `find_package` 并 `ament_target_dependencies`。

## 4. ROS 2 工作空间与 colcon

### 4.1 目录结构（背下来）

```
campus_ws/                 <- 工作空间根目录
├── src/                   <- 源码放这里
│   ├── campus_vision/     <- 一个包
│   │   ├── CMakeLists.txt
│   │   ├── package.xml
│   │   └── src/main.cpp
│   └── tdt_interface/     <- 另一个包（消息定义）
├── build/                 <- 编译中间产物（可删）
├── install/               <- 编译结果（可删，删了要重编）
└── log/                   <- 编译日志（可删）
```

**重要区分：**

- `src/` 里放的是**你写的代码**，要珍惜、要备份（git）。
- `build/`、`install/`、`log/` 是**自动生成的**，随便删，重新 `colcon build` 即可。

### 4.2 构建命令

```bash
cd ~/campus_ws
source /opt/ros/jazzy/setup.bash         # 先加载 ROS 2

colcon build                             # 编译所有包
colcon build --packages-select campus_vision   # 只编译一个包（快）
colcon build --packages-select tdt_interface campus_vision  # 编译两个

source install/setup.bash                # 加载编译结果，之后才能 run
ros2 run campus_vision campus_node       # 运行
```

### 4.3 为什么要 source 两次

```
source /opt/ros/jazzy/setup.bash     ← 让终端认识 ROS 2 本身
source ~/campus_ws/install/setup.bash ← 让终端认识你编的包
```

这叫做"**环境叠加**"：你的工作空间建立在系统 ROS 之上。
先底后上，顺序不能反。

### 4.4 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `ros2 run: package not found` | 没 source 或没编译 | `source install/setup.bash`，必要时重新 `colcon build` |
| 改了代码但不生效 | 没重新编译 | 重新 `colcon build --packages-select 包名` |
| 编译报"找不到消息包" | 消息包没先编译 | 先编消息包，再编用它的人 |
| 新开终端后命令没了 | 环境变量只对当前终端有效 | 重新 source |
| 权限错误 | 用了 sudo 编译 | 别用 sudo；删掉 build/install 后重新编 |

## 5. VSCode 配置

### 5.1 必装插件

| 插件 | 作用 |
| --- | --- |
| C/C++（Microsoft） | 语法高亮、跳转、补全 |
| CMake Tools | CMake 支持 |
| ROS（Microsoft） | ROS 2 支持 |
| Python | 如果你写 Python 脚本 |

### 5.2 c_cpp_properties.json（让跳转能用）

按 `Ctrl+Shift+P` → `C/C++: Edit Configurations (JSON)`，改成：

```json
{
    "configurations": [
        {
            "name": "ros2",
            "includePath": [
                "/opt/ros/jazzy/include/**",
                "${workspaceFolder}/src/**",
                "${workspaceFolder}/build/tdt_interface/rosidl_generator_cpp"
            ],
            "compilerPath": "/usr/bin/gcc",
            "cStandard": "gnu11",
            "cppStandard": "c++17",
            "intelliSenseMode": "gcc-x64"
        }
    ],
    "version": 4
}
```

> `includePath` 里加上"生成消息的头文件目录"，`#include <tdt_interface/msg/...>` 才不会报红。

### 5.3 终端里工作

VSCode 的终端（`` Ctrl+` ``）就是普通终端，所以上面所有命令照用。
建议开两个终端：一个跑游戏/节点，一个敲 `ros2 topic` 命令。

## 6. Git 极简入门

Git 是"代码的时光机"，能记录每次修改，改坏了随时能回退。新手只要记 6 条命令：

```bash
git init                      # 在当前目录初始化一个仓库（只做一次）
git add .                     # 把当前所有修改加入"待提交"
git commit -m "说明这次改了啥"  # 提交，生成一个存档
git log --oneline             # 看历史存档列表
git status                    # 看现在有哪些改动
git checkout -- 文件          # 撤销某个文件的修改（回到上次提交）
```

**习惯：**每完成一个小功能就 commit 一次。这样"改坏了"永远不怕。

> 小技巧：`build/ install/ log/` 不要提交，在项目根目录建个 `.gitignore` 写：
> ```
> build/
> install/
> log/
> *.pyc
> ```

## 7. 常用组合命令速查

```bash
# 找文件里哪里有某个函数
grep -rn "solvePnP" src/

# 看某话题频率
ros2 topic hz /camera/image_raw/compressed

# 实时看日志文件
tail -f ~/.local/state/tdt-campus-game/logs/*/relay.log

# 看某个进程还在不在
ps aux | grep campus_node

# 结束某个进程
pkill -f campus_node

# 编译并运行（一行）
colcon build --packages-select campus_vision && source install/setup.bash && ros2 run campus_vision campus_node

# 看磁盘占用
du -sh ~/campus_ws/*

# 清理编译产物（出怪问题时可以试）
rm -rf build/ install/ log/
```
